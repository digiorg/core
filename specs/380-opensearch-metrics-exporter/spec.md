# OpenSearch dedicated metrics exporter (#380)

## Decision and boundary
Chris selected the separate exporter for local implementation. This change does not alter the OpenSearch StatefulSet, image, heap, storage, or data. It adds one cluster-wide exporter, not one per node. Existing development desired state disables the OpenSearch security plugin; the backend connection is therefore HTTP without credentials and is not an approved production security design. Secured OpenSearch requires separately approved minimal API privileges, credential delivery and CA-verified TLS before use; no role or trust change is included here.

## Requirements
- R1: One singleton v1.11.0 exporter, immutable OCI index pin, `--es.all`, Recreate rollout, no Kubernetes API token, and bounded resources. Index contains the amd64 child measured in the historical isolated test. This does not establish other architectures' functional compatibility.
- R2: Only the exporter's dedicated Service is selected by the ServiceMonitor; remove the former direct `/_prometheus/metrics` scrape. Do not collapse distinct backend nodes; all-node mode is intended to preserve them. Cluster aggregates belong to the one exporter.
- R3: Observe actual exporter series: cluster-info and collector-specific success are not generic Prometheus `up`; do not invent `elasticsearch_up`.
- R4: Test rendered workload/discovery, negative shared-label topology, identities, metrics and pins, then run the full exact-candidate repository gate. Historical isolated single-node data is bounded evidence only.
- R5: No runtime change, publication, merge, credential/RBAC modification, or residual-risk acceptance in this work.
- R6: Chris authorized local exporter-only ingress/egress NetworkPolicy. Select only exporter Pods; allow ingress TCP 9114 from Prometheus Pods in monitoring; egress TCP 9200 to chart-rendered OpenSearch Pods and TCP/UDP 53 to kube-system CoreDNS Pods. Namespace and pod selectors must be in the same peer. Reject broad peers, extra ports, missing isolation and selector mismatch with negative rendered fixtures.

## Network containment and unverified boundaries
The chart-rendered Prometheus resource is `monitoring/prometheus-kube-prometheus-prometheus`; operator v0.92.1 [source](https://github.com/prometheus-operator/prometheus-operator/blob/5d9ff4a3fe45a51b7fead3c6ad1c3093176a10e5/pkg/apis/monitoring/v1/prometheus_types.go#L124-L133) reserves `operator.prometheus.io/name` for that resource name on Pods. OpenSearch chart 3.7.0 renders Pods with name `opensearch`, instance `opensearch`, component `opensearch-cluster-master`. Repository `scripts/local-setup.nu` identifies CoreDNS Pods as `k8s-app=kube-dns` and EndpointSlices as `kube-dns` in `kube-system`. These are source contracts, not live observations. The existing Kyverno app namespace policy excludes `platform-db`; other live policies are unknown and Kubernetes policies are additive.

The exporter unconditionally exposes `/probe`: this policy is containment, not route removal. Authorized scraper Pods can invoke it, and allowed destinations remain reachable. CNI enforcement, Service DNAT, node-local DNS, host-network and node/kubelet probe behavior, existing additive policies and Pod-label control remain unverified. No live proof or risk acceptance is asserted. A separately authorized runtime exercise must test allowed metrics, DNS, backend and probes plus unauthorized Pod-IP/Service-IP and exporter egress negatives; if node-local DNS requires a new exception, stop for a specific decision rather than broaden this policy.
